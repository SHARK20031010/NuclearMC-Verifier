# 细链条：五种动作 × 失效槽位

**v0.4**

上一版（v0.3）只有 7 个环。用户说"不够细，没覆盖所有可能的错误"。

**诊断：问题不在于环太少，而在于环不是出错的单位。**

- 一个环（比如"源"）里有十几件事，全错在里面也看不出来
- 就算把环拆到 50 个，仍然只能覆盖"我想到了的那些"
- **列不完** —— 这是本源问题

**换办法：不列举错误，而是给出一套能生成所有错误的规则。**

---

# 一、封闭性论证

**命题：蒙特卡洛程序里任何一行代码，对数据只做五件事之一。**

| 动作 | 干什么 | 例子 |
|---|---|---|
| **定** | 建立一个东西，并给它取值 | 建材料、建体积、注册过程、设截断 |
| **抽** | 从一个分布里取一个值 | 抽能量、抽方向、抽作用种类、抽自由程 |
| **取** | 从已有对象读一个值 | 读 track 的能量、读 step 的沉积、读过程的字段 |
| **记** | 把一个值放进一个箱或一个和 | 累加能量沉积、填直方图、计数 |
| **换** | 改变一个值的表示方式 | 单位换算、除以事件数、乘响应系数 |

这五件事是**穷尽**的：一行代码要么建立东西、要么产生值、要么读值、要么存值、要么改表示。没有第六种。

**加一条横轴：控制流** —— 这件事**什么时候执行、执行几次**。

**于是错误空间 = （链条上的位置）× （五种动作）× （该动作的失效槽位）。**

这个空间是**生成的**，不是**列举的**。只要槽位表是穷尽的，覆盖就是穷尽的。

---

# 二、五种动作的失效槽位表

## 动作 A：定（define）—— 4 个槽位

| 槽位 | 出错形式 | 实测例子 |
|---|---|---|
| **有无** | 该建的没建 | T1-2 没注册中子弹性散射构造器 → 透射率差 2 倍 |
| | | T4-3 没设 Birks 系数 → 中子光产额高估 5.6 倍 |
| **重复** | 建了两次，后者静默覆盖前者 | 同名材料只打一行 `G4cout` 且两个都入表，按名查永远返回第一个 |
| **身份** | 名字/标识本身携带副作用或歧义 | 材料名 `G4_WATER` → 热散射开启；成分逐位相同的 `H2O`/`water` → 不开 |
| **取值** | 建的参数值错 | T4-1 平行束当点源、T2-3 事件数写死 100 |

## 动作 B：抽（sample）—— 6 个槽位

| 槽位 | 出错形式 | 实测例子 |
|---|---|---|
| **变量** | 抽错了东西 | — |
| **定义域** | 抽样范围错 | `/gps/pos/confine` 必须给 physical volume 名；截断型分布能量拒绝循环**无迭代上限 → 挂死** |
| **形状** | 分布类型错 | T4-1/T4-2 方向根本没抽，写死成常量 → 零发散平行束（超几何上限 11.8 / 44 倍） |
| **参数** | 参数从哪来、对不对 | T3-3 漏 Na-24 的 2.754 MeV 线（占空气比释动能 62.1%）→ 低 2.59 倍 |
| | | T3-4 Co-60 强度写 0.60（应≈1.00）；T6-4 Ir-192 的 604.4 keV 写成 82.2（应 8.2） |
| **实现** | 抽样算法本身写错 | 逆 CDF 循环漏 `break`、拒绝法无上限 |
| **相关性** | 该相关的当成独立 | 默认各向同性独立抽（`G4DeexPrecoParameters.hh:268 fCorrelatedGamma = false`）；Co-60 两个 γ 时间严格相等、角关联默认关 |

## 动作 C：取（fetch）—— 5 个槽位

| 槽位 | 出错形式 | 实测例子 |
|---|---|---|
| **谁** | 读错了对象 | T3-2 用 `GetProcessDefinedStep()` 判产物核来源，实测该字段只有 ionIoni/NoProcess/Radioactivation/hIoni/conv → **输出空表**。真信息在 `GetCreatorProcess()` |
| **何时** | 在错误的时刻取值 | T6-1 取 `track->GetKineticEnergy()`，而 track 走到首步时**已经作用完** → 576 个光子（28%）记成 0 |
| | | T1-4 读**前步点**判边界，而 `G4Transportation.cc:508` 把标志设在**后点** → <1 MeV 伽马 1 vs 65 |
| **哪里** | 读错范围/体积/粒子种类 | — |
| **哪个字段** | 同一对象上读错成员 | T3-2 同上（`GetProcessDefinedStep` vs `GetCreatorProcess`） |
| **存在性** | 读一个可能为空的东西，静默给 0 | `G4StepPoint.hh:188 G4double fWeight = 0.0;` → 该步贡献整体归零 |

## 动作 D：记（accumulate）—— 6 个槽位

| 槽位 | 出错形式 | 实测例子 |
|---|---|---|
| **记什么** | 量的定义错 | T5-1 线能分母用**直径 1 µm**，应**平均弦长 4r/3 = 0.667 µm** → 全谱偏小 1.5 倍 |
| **在哪记** | 记错体积/层面 | T4-4 `if (g_eCry + g_eDead > 0.)` → 死层沉积也算探测到（10 mm 处低报 1.39 倍） |
| **何时记** | 记错步/时刻 | 计分乘的是**前步点**权重（20 处 scorer 中 19 处），唯一例外 `G4PSSphereSurfaceFlux.cc:140` 用后步点 |
| **权重** | 忘了乘权重、或乘错 | 16 个计分器各有 `Weighted(bool)`，默认不一；`G4PSVolumeFlux.cc:82` **无开关、永远乘** |
| **分箱** | 箱边界/宽度错 | T4-2 无 `if(gEdep>0)` 保护 → 1.25 keV 第 0 道占 **12.4%** 伪零能峰 |
| **聚合** | 事件内/运行级聚合错 | `entry` 是**命中步数不是事件数**（实测 DD entries=2406 而 N_events=5000）→ 误当采样数代入 √N 严重高估精度 |

## 动作 E：换（convert）—— 5 个槽位

| 槽位 | 出错形式 | 实测例子 |
|---|---|---|
| **分母** | 除以什么错 | T3-1 `A0 = Rp*(1-exp(-lam*Tirr))/lam;` 多除一个 λ；`Rp = phi*pCap/V` 少乘束流面积 πR² → 净放大 **1222 万倍** |
| **单位链** | 每一步换算错 | Geant4 只有 `gray`，无 `Sv`/`sievert`（全源码树 sievert 仅 1 命中且在 vendored CLHEP）→ 剂量当量只能自己算 |
| **响应系数** | 该乘的系数缺或错 | Geant4 **不内置 ICRP 转换系数**（全源码树 ICRP 只出现在材料名里） |
| **归一化基准** | 归一到什么没定 | `/score/` 输出**完全不归一化**（写 sum_wx / sum_wx² / n 三个累加和）；实测 20000 事件输出 ≈ 5000 事件的 **1081 倍** |
| **误差** | 误差没算或算错 | `G4StatDouble::rms()` 有实现但**全树零调用**；框架不算也不输出统计误差 |

## 横轴：控制流 —— 4 个槽位

| 槽位 | 出错形式 | 实测例子 |
|---|---|---|
| **层级** | 该在步级/事件级/运行级做的事放错层 | T6-2 去重集合只在 `BeginOfRunAction` 清空，而 trackID 每事件重排（`G4RunManager.cc:445`）→ 产额低 53%、随事件数非物理漂移 |
| **次数** | 循环次数/事件数错 | T2-3 硬编码 `nEvents=100` 不可覆盖；20 个种子极差 3 倍、相对统计误差 27% |
| **条件** | 判断条件写错 | T1-2 用了 `"elastic" in name`，而 **`"inelastic"` 里就含 `"elastic"`** → 规则静默失效 |
| **顺序** | 该先做的后做 | 过程去重按 (Type,SubType)，**后注册者被静默丢弃**只抛 `Run0111` JustWarning（`G4PhysicsListHelper.cc:441,456`）|

# 三、槽位总数：31 个

| 动作 | 槽位数 |
|---|---|
| 定 | 4 |
| 抽 | 6 |
| 取 | 5 |
| 记 | 6 |
| 换 | 5 |
| 控制流 | 4（横轴，作用于以上每一个） |
| **合计** | **30 + 1 条横轴** |

**这 31 个槽位是穷尽的**——因为五种动作穷尽，每个动作的失效方式也就是那么几种（东西有没有、值对不对、时候对不对）。

# 四、物理链条展开成「抽签序列」

上一版 7 个环太粗。真正的粒度是**每一次从分布里取一个值**。

以「γ 穿过铅板求透射率」为例，物理链条展开成 ~25 个节点：

```
【源】决定粒子是什么、从哪来
 A1 发射率/活度         → 决定归一化的分母
 A2 粒子种类            → 电子？光子？中子？
 A3 能量                → 单能？谱？谱的每个数从哪来？
 A4 方向                → 各向同性？定向？点源还是面源？
 A5 出发点              → 点？面？体？
 A6 发射时刻            → 稳态？脉冲？
 A7 相关发射            → 多条 γ 是否同时、是否有角关联？

【输运】对每个粒子循环
 B1 到哪作用            ← 抽自由程，用哪个截面
 B2 作用种类            ← 抽过程（光电/康普顿/对产生）
 B3 作用后的能量与方向   ← 抽散射角分布
 B4 产生哪些次级、几个   ← 抽级联
 B5 次级能量方向
 B6 次级跟不跟          ← 产生截断
 B7 不稳定核何时衰变     ← 衰变时间
 B8 到边界怎么办         ← 反射？杀死？漏出？

【计分】在每一步/每一事件
 C1 记什么量            → 沉积能量？径迹长？穿过次数？
 C2 在哪记              → 哪个体积、哪个面
 C3 什么时候取           → 前步点还是后步点
 C4 权重多少            → 方差缩减的账
 C5 进哪个箱            → 能量分箱、空间分箱
 C6 事件内怎么聚合

【换算】跑完之后
 D1 除以什么            → 事件数？源粒子数？时间？
 D2 单位链              → MeV→J→Gy→Sv
 D3 响应系数            → 剂量转换因子
 D4 误差                → 统计误差怎么算、算不算
```

**25 个节点 × 每个节点上可能发生的动作（定/抽/取/记/换）= 出错位置。**

# 五、代码链条展开成「语句序列」

```
构造期
 ├─ Construct()
 │   ├─ 材料：AddElement / AddMaterial / AddMaterialPropertiesTable   [定][换]
 │   ├─ 实体：new G4Box/G4Tubs/... + 布尔运算                          [定]
 │   ├─ 放置：new G4PVPlacement(mother, ..., pSurfChk)                 [定][控制]
 │   └─ 挂探测器：SetSensitiveDetector / 建 scorer                     [定]
 ├─ 物理列表构造函数 RegisterPhysics()                                  [定][控制-顺序]
 └─ SetUserAction(源 / Run / Event / Stepping Action)                  [定]

初始化期
 ├─ CloseGeometry()
 ├─ ConstructProcess()   ← 过程、模型、截面数据集在这里注册            [定]
 └─ BuildPhysicsTable()  ← 能损过程的模型（eIoni/eBrem/hIoni）到这里才注册 [定]

运行期（三层嵌套）
 ├─ GeneratePrimaries()          [每事件] [抽][定]
 └─ for track:
     └─ for step:
         ├─ 选过程、抽自由程      [抽]
         ├─ 推进、处理边界        [抽][控制]
         ├─ 算沉积能量            [抽]
         ├─ UserSteppingAction    [每步] [取][记]
         └─ ProcessHits           [每步] [取][记]
     EndOfEventAction             [每事件] [记][控制-层级]
 EndOfRunAction / main 末尾       [每运行] [换]
```

# 七、为什么这样就"覆盖所有可能"

1. **五种动作穷尽** —— 任何一行代码对数据只做这五件事。
2. **每个动作的失效槽位穷尽** —— 东西要么有要么没有；值要么对要么错；时候要么对要么错。没有第三种。
3. **链条位置可枚举** —— 物理链条展开到"每一次抽签"是有限的（这个例子 25 个）；代码链条展开到"每一处读写"也是有限的。
4. **乘起来就是错误空间** —— 25 × 若干槽位 ≈ 150 个具体位置。**有界、可枚举、可推导。**

关键区别：**这个 150 不是数出来的，是乘出来的。** 换一个程序（换题目、换 Geant4、换 OpenMC、换 FLUKA），链条长度会变，但槽位表不变——所以覆盖性论证跟着框架走，不跟着例子走。

# 八、诚实说：这个框架仍覆盖不到的

1. **"整体量算错了"** —— 比如公式本身推导错（T3-1 多除 λ 属于"换-分母"槽位，能装下；但如果用户要的量本身定义错了，比如把"吸收剂量"和"剂量当量"搞混，那是环 0，链条上没有落点）。**环 0 永远是框架外。**
2. **"物理模型本身的适用范围"** —— 比如本机 G4NDL4.7.1 在 14 MeV 下从不产生 Fe-53。程序没错、代码没错、数据也没错，是**模型能力边界**。落不进槽位表，只能靠"这个数凭什么可信"单独问。
3. **"链条上的错误互相抵消"** —— 两个错凑巧抵消，结果看起来对。槽位表能发现两个错，但发现不了它们互相掩盖。需要对照实跑。
4. **槽位表本身的验证** —— 上面 31 个槽位里，只有 9 个有实测的错在打中，其余 22 个的机制来自前几轮的源码核验（不是这一版新做的）。**还有没有第 32 个槽位，现在无法证明没有。**
5. **控制流那 4 个槽位最弱** —— 层级/次数/条件/顺序都是从实测错里归纳出来的，不像"定抽取记换"那样有封闭性论证。

# 九、下一步能做的三件事

1. **拿 31 个槽位过一遍 94 点清单** —— 把 94 个点当"实体"、槽位当"属性"，看哪一个点落不进任何槽位。落不进的就是槽位表的漏洞。
2. **把 24 题重写成"每题一条抽签序列"** —— 每题列 25 个节点，AI 逐节点自问"这一节点上我做对了吗"。这是"顺着链条走"的具体形态，比问清单细得多。
3. **补环 0 的问法** —— 那五处程序里没有落点的地方（要什么物理量/容差/绝对源强/响应系数/统计误差），怎么问才能问得具体，还没定。
