# 基本原理 → 链条 → 参数

**目的**：把"有哪些决策点"从**枚举**改成**推导**。
枚举的毛病是永远说不清漏没漏；推导能说清为什么完整。

---

## 1 基本原理

任何蒙卡输运程序算出来的数，都是这三样东西的复合：

```
       源  S          输运  T          计分  R
粒子长什么样、   跟物质怎么作用、    在哪儿、记什么、
从哪来、多强     走到哪、什么时候停    记多少
        │              │              │
        └──────────────┴──────────────┘
                       │
                    权重 W
              （中间每一处"抄近路"都要记账）
                       ↓
                     结果 θ̂
```

写成式子（不用看懂，看结构就行）：

```
θ = ∫ S(P) · T(P→P') · R(P')  dP dP'
θ̂ = Σ  权重 × 记分        （蒙特卡洛估计量）
```

**核心一句话**：
> 一个参数只要影响结果，就必然作用在 **S、T、R、W** 四个地方之一。
> 不影响这四个地方的参数，不影响结果。

**所以决策点的完整集合 = S 的参数 ∪ T 的参数 ∪ R 的参数 ∪ W 的参数。**
这是推出来的，不是数出来的。

---

## 2 每一环"必须交代"什么——推导过程

每一环本质上都是"**从一个分布里抽一个值**"。
要说清一件事，必须交代三样：**抽什么、按什么分布抽、抽完怎么记账**。

把这三样套到三个环节上，就得到下面 18 问。

### S 源项 —— 6 问

| # | 问题 |
|---|---|
| S1 | 是什么粒子、什么电荷态？ |
| S2 | 能量怎么来的？（单能／连续谱／由衰变级联产生） |
| S3 | 方向怎么来的？（各向同性／定向／面法向／实测分布） |
| S4 | 从哪儿出发？（点／面／体；在几何的哪一侧） |
| S5 | 什么时候出发？（稳态／脉冲／时间窗） |
| S6 | 绝对强度多少？（和什么归一） |

### T 输运 —— 6 问

| # | 问题 |
|---|---|
| T1 | **几何**：每个体积的边界曲面与尺寸 |
| T2 | **材料**：成分、密度、温度、光/电响应属性 |
| T3 | **作用类型**：装了哪些过程与模型（弹性／非弹性／俘获／裂变／衰变／电磁…） |
| T4 | **数据来源**：截面、能损、核数据来自哪个评价库、哪一版、什么温度 |
| T5 | **边界与截断**：走到什么时候停（能量下限、产生截断、步长上限、时间上限） |
| T6 | **偏置**：为了算得快用了什么加速手法 |

### R 计分 —— 5 问

| # | 问题 |
|---|---|
| R1 | **记什么量**？（通量／流量／沉积能／比释动能／剂量／活化／响应） |
| R2 | **在哪儿记**？（哪个体积／哪个面／网格多细／算哪个方向） |
| R3 | **怎么加权**？（权重、余弦加权、径迹长度加权…） |
| R4 | **归一到什么**？（每源粒子／每 cm²／每秒／每 Bq） |
| R5 | **误差多大**？（事件数、统计误差定义、收敛判据） |

### W 权重记账 —— 1 问（但贯穿全程）

| # | 问题 |
|---|---|
| W1 | 中间每一处"抽样分布 ≠ 真实分布"的地方，**账还回来了吗**？ |

> 类比：为了抄近路，你让粒子多走某条道。这条路相当于"一条顶三条"。
> 走到终点时必须补记"三条"，不补记，总数就少算了。

**合计 6 + 6 + 5 + 1 = 18 问。**

## 3 链条 → 参数：18 问落地成什么

每个问题往下走，就对应到具体程序的参数。
以 Geant4 为例（**这只是"实例"，不是原理本身**）：

| 问 | Geant4 里对应什么 |
|---|---|
| S1 | `G4ParticleGun::SetParticleDefinition` / `/gps/particle` |
| S2 | `SetParticleEnergy` / `/gps/ene/type` + 直方图 |
| S3 | `SetParticleMomentumDirection` / `/gps/ang/type` |
| S4 | `SetParticlePosition` / `/gps/pos/type`、`/gps/pos/centre` |
| S5 | `/gps/time/*` |
| S6 | **程序里没有**（见第 5 节） |
| T1 | `G4VSolid` 子类 + `G4PVPlacement` |
| T2 | `G4Material` + `G4MaterialPropertiesTable` + Birks |
| T3 | 物理列表 / `RegisterPhysics` / `/process/activate` |
| T4 | `G4NDL`、`G4EMLOW` 等数据目录；`G4CrossSectionDataSet` |
| T5 | `/run/setCut`、`G4UserLimits`、`G4StepLimiterPhysics` |
| T6 | `G4WeightWindowStore`、`BiasCrossSectionByFactor` |
| R1 | `G4VPrimitiveScorer` 子类 / 自定义 `G4VSensitiveDetector` |
| R2 | 计分网格、`G4PSFlatSurfaceFlux` 等 |
| R3 | scorer 的 `Weighted()` 开关；`G4Step::GetWeight` |
| R4 | **程序里没有**（用户自己后处理） |
| R5 | **Geant4 不算也不输出统计误差**（见第 5 节） |
| W1 | `G4Track::GetWeight` 的传播 |

**这样做有一个可检验的好处**：
把程序里所有可设置项（Geant4 11.2.2 实测 304 条 UI 命令、81 个 EM 参数、
31 个强子参数）**逐条往这 18 问里塞**。
- 塞得进去 → 说明这 18 问覆盖得住
- 塞不进去的 → 要么第 18 问漏了一问（**发现新维度**），要么这个参数跟物理无关

这就是"完备性"的论证方式：不是"我数全了"，而是"我推出来的框架装得下所有数出来的项"。

## 4 错误分类：按环节，不按现象

链条一立，错误分类自己就出来了：

| 环节错 | 后果 | 能不能自检出来 |
|---|---|---|
| **S 错** | 算的根本不是那个问题 | 不能（程序不知道你想问什么） |
| **T 错** | 物理过程算错了 | 部分能（配置可见的那部分） |
| **R 错** | 数读错了 | **不能**（程序不知道你要什么量） |
| **W 错** | 期望值被改变了 | 理论能（拦抽样记账），实践难 |
| **统计不足** | 数在抖，不是错 | 能（跑两次看动不动） |

## 5 ★ 这一版框架立刻解释了一个实测结果

把 24 题实测出来的 14 个错，按环节归类：

| 环节 | 个数 | 题 |
|---|---|---|
| **S 源** | **5** | T3-1（源强归一）、T3-3（漏 γ 线）、T3-4（强度抄错）、T4-2（点源写成平行束）、T6-4（强度抄错） |
| **T 输运** | **2** | T1-2（少装中子弹性）、T4-3（缺 Birks 系数） |
| **R 计分** | **7** | T1-4（记的时刻取错）、T3-2（记录对象取错）、T4-1（量定义错）、T4-4（记错区域）、T5-1（量定义错）、T6-1（记的时刻取错）、T6-2（去重记账错） |

**R（计分）占了一半。**

而之前那 17 条护栏规则查的是什么？查的是 **T 环节里"配置被改了"的那部分**
（物理列表、EM 参数、截断）。

**所以"护栏抓不到错"不是护栏写得差，是它站错了环节。**
实测：T 环节只有 2 个错，护栏抓到 1 个 —— **在它自己那一环里，命中率是 1/2，不算差。**

这个解释是**推导出来的**，不是事后编的。它同时预言了：
> 想提高命中率，护栏必须往 S 和 R 两环挪。

## 6 为什么这比"枚举参数"好

| | 枚举 | 推导 |
|---|---|---|
| 完整性 | 说不清（"我尽量数全"） | 可论证（框架装得下所有数出来的项） |
| 换程序 | 要重数一遍（OpenMC / FLUKA 各一套） | 框架不变，只换实例 |
| 有界性 | 几百上千个，无界 | **18 问，有界** |
| 解释力 | 无 | 能解释"为什么护栏抓不到" |
| 对审稿人 | "这不就是 linter 吗" | 有原理层，不是清单堆 |

**这一条直接回答最早的批评**：原 idea 被判"Agent 能做几百上千个物理决定，无界"。
现在它是**有界的 18 问** —— 因为每一环"必须交代什么"是推出来的，
不是把程序的可设置项数出来的。

## 7 对护栏的含义（三环各要什么）

| 环 | 护栏能做什么 | 做不了什么 |
|---|---|---|
| **S** | 查代码里源是怎么定义的；追问"和什么归一"；核对谱线表出处 | 判断"源选得对不对" |
| **T** | 查运行配置（已有 17 条规则） | 看见下游的 R 错 |
| **R** | 查"记的是什么量、在哪记、分母是什么、误差多大" | 判断"这个量的定义对不对" |
| **W** | 查"哪里偏置了、账还了没有" | — |

**这正好对上用户定的"老师傅"定位**：每一环都只**问**，不下结论。

## 8 待商榷

1. **S6 / R4 在程序里根本没有**（Geant4 没有"源强"概念，一切按每源粒子计）。
   这类"程序不提供的环节"应该单独成一类：**护栏要明说"这件事程序不做，你得自己做"**。
   这与之前核验出的 **M12 功能缺位** 是同一件事。
2. **W 这一环最弱**：本机实测 Geant4 里 `XBiasSurvivalProbability` 之类的
   权重补偿是死代码，而 `G4Track::fWeight` 只在 20 处 scorer 里各自乘 ——
   所以"账还了没有"很难自动查。
3. 18 问是**这一版**的推导结果。第 3 节的"塞参数"检验做完之后，
   很可能要加一两问（比如"随机数种子/可复现性"算不算一环）。
4. 目前只用 24 题实测的 14 个错做过校验，样本小。
