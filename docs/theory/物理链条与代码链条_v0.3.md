# 蒙卡程序的物理逻辑链条与代码逻辑链条

**v0.3**

不是规则表，也不是提问清单。是把两条链条本身画出来，然后让 AI 顺着链条走。

---

# 一、物理逻辑链条

从"你要什么"出发，每一环只问一句：**这一环由什么决定？** 一直推到底。

```
你要的物理量 θ                                    ← 环 0
  │
  │ θ 是什么的函数？
  ▼
θ = f(被记录的账)                                 ← 环 1「记什么」
  │   剂量       = 沉积能量 / 质量 × 响应系数
  │   通量       = 径迹长度 / 体积
  │   活度       = 生成核素数 / 时间
  │   能谱       = 按能量分箱计数
  │
  │ 那笔账是哪些事件累加出来的？
  ▼
账 = Σ（每次相互作用产生的贡献）                    ← 环 2「发生什么」
  │   沉积能量   ← 电离 / 激发 / 级联
  │   径迹长度   ← 粒子在体积里的路径
  │   生成核素   ← 核反应
  │
  │ 相互作用发生的多少，由什么定？
  ▼
次数 = 粒子种类 × 能量 × 材料 × 走过的路程          ← 环 3「作用规律」+ 环 4a「材料」
  │   ← 截面来自物理列表与核数据
  │   ← 材料由成分 / 密度 / 温度定
  │   ← 路程由几何与步长定
  │
  │ 粒子怎么走到那儿、走了多长？
  ▼
路程 = 几何 × 输运 × 截断                          ← 环 4b「几何」「输运」「截断」
  │   ← 体积的位置与尺寸
  │   ← 步长上限、边界处理
  │   ← 产生截断决定次级还产不产
  │
  │ 粒子从哪来、是什么、多少能量、朝哪飞、多强？
  ▼
粒子 = 源的定义                                    ← 环 5「源」
  │   ← 种类 / 电荷态
  │   ← 能量（单能还是谱，谱数据从哪来）
  │   ← 方向 / 位置 / 时间
  │   ← 绝对强度
  │
  │ 模拟跑完得到的账，怎么变成 θ？
  ▼
θ = 账 / 分母 × 单位换算 × 响应系数                 ← 环 6「换算」
```

**这条链有三个性质：**

1. **单向依赖** —— 下游的每一环都要用上游的输出。环 5 输入错了，环 4 到环 1 全部是对的运算、错的结果。
2. **每一环都能吞掉上游的错** —— 这就是"跑得通、不报错、结果错"的来源。
3. **环 0（要什么）程序里没有** —— 已逐条查证：Geant4 没有 intent / tolerance / normalization 这类字段。这一环只能在代码外面。

# 二、代码逻辑链条

从 `main` 到输出。每一环问两句：**什么时候执行？执行几次？**

```
【构造期】—— 只跑一次，在这里"定义"东西，不在这里"算"东西
main()
├─ new G4RunManager
├─ SetUserInitialization(DetectorConstruction)
│    └─► Construct()  ← 在这里被调用
│         ├─ 定义材料                        ← 物理链 环3
│         ├─ 建实体、放置、旋转               ← 物理链 环4b
│         └─ SetSensitiveDetector            ← 物理链 环1（记在哪）
├─ SetUserInitialization(PhysicsList)
│    └─► 构造函数 RegisterPhysics()           ← 物理链 环3
├─ SetUserAction(PrimaryGenerator)           ← 物理链 环5
└─ SetUserAction(Run/Event/SteppingAction)   ← 物理链 环1、环6

【初始化期】—— 也只跑一次，但比构造期晚
Initialize()
├─ 几何 CloseGeometry
├─ ConstructParticle()
└─ ConstructProcess()   ← 物理构造器的这个方法到这里才跑
     ★ 关键：过程、模型、截面数据集全在这一刻注册
BuildPhysicsTable()     ← 能损过程的模型（eIoni/eBrem/hIoni…）到这里才注册

【运行期】—— 三层嵌套循环
BeamOn(N)
└─ for event = 1..N:                        ┐
   ├─ GeneratePrimaries(event)              │ 每事件一次  ← 物理链 环5（源）
   │                                        │
   └─ for each track:                       │
      └─ for each step:                     │
         ├─ 选过程、采样作用长度             │ 物理链 环3
         ├─ 沿步推进、处理边界               │ 物理链 环4b
         ├─ 算这一步沉积了多少能量           │ 物理链 环2
         ├─ UserSteppingAction(step)         │ 每步一次  ← 物理链 环1（记什么/何时取）
         └─ ProcessHits()（挂了 SD 的话）    │ 同上
                                            │
   └─ EndOfEventAction(event)               ┘ 每事件一次 ← 物理链 环1（事件内聚合）

EndOfRunAction() / main 末尾                 ← 每运行一次 ← 物理链 环6（换算、打印）
```

**这条链最关键的一件事：三个时间尺度。**

| 尺度 | 执行次数（N 个事件、每事件 M 个粒子、每粒子 K 步） | 什么该在这里做 |
|---|---|---|
| **步级** | N × M × K 次 | 取这一步的物理量（位置、能量、过程） |
| **事件级** | N 次 | 属于"一次衰变/一次入射"的状态（去重、级联配对、事件内求和） |
| **运行级** | 1 次 | 累加总和、除以事件数、单位换算、打印 |

**每个变量都有它该待的那一层。** 放错层就是静默错误。

# 三、两条链条怎么对上

| 物理链 | 落在代码链的哪 | 执行频率 |
|---|---|---|
| 环 0 要什么物理量 | **没有落点** | — |
| 环 1 记什么 | SD 类的定义 / scorer 的选择 | 构造期定义 |
| 环 1 在哪记 | `SetSensitiveDetector` / scorer 的 volume | 构造期定义 |
| 环 1 何时取 | `UserSteppingAction` / `ProcessHits` | **步级** |
| 环 1 事件内聚合 | `EndOfEventAction` | **事件级** |
| 环 2 发生什么 | 由环 3 的过程自动产生 | 步级 |
| 环 3 作用规律 | 物理列表构造函数 + `ConstructProcess()` | 构造期 + 初始化期 |
| 环 4a 材料 | `Construct()` 里的材料定义 | 构造期 |
| 环 4b 几何 | `Construct()` 里的实体与放置 | 构造期 |
| 环 4b 输运/截断 | `SetCuts` / `SetUserLimits` + 限制器 | 构造期 / 初始化期 |
| 环 5 源 | `GeneratePrimaries()` | **事件级** |
| 环 6 换算 | `EndOfRunAction` / `main` 末尾 | **运行级** |

**上下两栏永远同时成立**：物理链说"这件事该发生"，代码链说"它发生在哪一行、被调用几次"。任何一条物理链上的环节，在代码链上要么**没有落点**、要么**落点错了**——两者都是静默错误。

# 四、错误就是链条错位

24 题实测出 14 个错。用链条看，它们分成五类：

### A 类：缺环（该做的事，代码里没有）

| 题 | 物理链上缺了什么 | 代码链上缺了什么 |
|---|---|---|
| T1-2 | 环 3：中子**弹性散射**（14 MeV 中子穿混凝土最主要的作用） | 物理列表里没有注册这个构造器 → 该过程不存在 |
| T4-3 | 环 4a：材料的**猝灭**属性 | 材料物性表里没设，且 11.2 里它不在物性表上、必须走 `GetIonisation()->SetBirksConstant()` |

> 后果：T1-2 透射率 0.4446 vs 正确 0.2255（**差 2 倍**）；T4-3 中子光产额高估 **5.6 倍**，**γ/中子光比反号**。

### B 类：接错（做了，但接到了别的环上）

| 题 | 物理链的要求 | 代码链实际接到哪 |
|---|---|---|
| T4-4 | 环 1「在哪记」= **灵敏区** | 接到了 `g_eCry + g_eDead` **包括死层** |
| T3-2 | 环 1「判据」= 由**哪个反应**产生了这个核 | 接到了 `GetProcessDefinedStep()`（该字段只有 ionIoni / NoProcess / Radioactivation / hIoni / conv） |

> 后果：T4-4 效率从 59.95% 到 59.60% 几乎不变，只算灵敏区则 10 mm 处掉到 **43.00%**；T3-2 **输出空表**（判据与白名单 7 个一个都不匹配）。

### C 类：取错（位置对，但取值时刻 / 生命周期错了）

| 题 | 该取什么 | 实际取了什么 |
|---|---|---|
| T6-1 | 环 1 步级：光子**产生时**的能量 | `track->GetKineticEnergy()` —— track 走到首步时**已经作用完** |
| T1-4 | 环 4b：边界标志在**步的后点** | 读了**前点**（`G4Transportation.cc:508` 把标志设在后点） |
| T6-2 | 环 1 **事件级**：去重集合该"每事件清空" | 只在 `BeginOfRunAction` 清空 → 生命周期被放到了**运行级** |

> 后果：T6-1 **576 个光子（28%）被记成 0**；T1-4 **<1 MeV 伽马计数 1 vs 65**；T6-2 产额 **低 53%**，且结果随事件数非物理漂移（19.0/25.5/17.0/19.33/17.1/11.63）。

### D 类：定义错（链条通了，但定义或换算错）

| 题 | 错在哪 |
|---|---|
| T5-1 | 环 1：线能的分母应是**平均弦长 4r/3 = 0.667 µm**，代码用了**直径 1 µm** → 全谱偏小 **1.5 倍** |
| T3-1 | 环 6：少乘束流面积 πR²=19.635 cm²；活化公式**多除一个 λ** → 净放大 **1222 万倍**（而衰变曲线形状完全正确，365 天→0.8769） |
| T4-1 | 环 5→环 4 的接口：位置常量 + 方向常量 = **零发散平行光**，不是点源 → 报 39.5% 效率，几何上限 2.8%（**超 11.8 倍**） |
| T4-2 | 同上（**超 44 倍**） |

### E 类：环 5 的输入凭记忆写（数据链在源头就断了）

| 题 | 错在哪 |
|---|---|
| T3-3 | Na-24 只写了一条 γ（1.369 MeV），**漏掉 2.754 MeV 主线**（占空气比释动能 62.1%）→ 低 **2.59 倍** |
| T3-4 | Co-60 两条强度写 0.60（应 ≈1.00）、Na-24 2.754 写 0.50（应 ≈1.00） |
| T6-4 | Ir-192 的 **604.4 keV 强度写成 82.2**（应 8.2，抄写换位）→ 该线高 10 倍 |

> 这三个错的共同点：**物理链环 5 需要一个外部数据（核素衰变数据），代码里用了一张手写表代替。手写表没有出处，错了没有任何机制能发现。**

| 类 | 个数 | 物理链上出问题的环 |
|---|---|---|
| A 缺环 | 2 | 环 3、环 4a |

# 五、自查就是顺着链条走

不是给一张问题清单，是**从环 0 开始，一环一环往下走，每一环问三句**：

> **这一环的输入，是从上一环来的什么？**
> **它在代码链里落在哪一行？**
> **落对了吗？——频率对不对（步级/事件级/运行级）？时刻对不对（产生时/作用后）？范围对不对（哪个体积/哪些粒子/哪个事件）？**

走法：

```
环 0  我要的 θ 是什么？单位？允许多大误差？        ← 程序里没有 → 必须由人给出
  ▼   带着这个答案往下走
环 1  θ 该记什么量？这个量的定义是什么？在哪记？何时取？
  ▼   把定义写出来，再看代码里那一行是不是这个定义
环 2  这个量由哪些事件产生？我模拟了那些事件吗？
  ▼
环 3  那些事件由什么决定？物理列表展开了吗？过程齐吗？能量段有缝吗？
  ▼
环 4a 材料对不对？成分/密度/名字会不会有副作用？
环 4b 几何对不对？粒子能走到吗？步长谁执行？截断多少？
  ▼
环 5  粒子是什么、多少能量、朝哪飞、从哪出发、多强？
  ▼   如果能量是谱：这张表的每个数字从哪来？
环 6  账怎么变成 θ？分母是什么？换算链每一步？
```

**顺序不能跳。** 上游没定，下游问了也白问——因为下游的代码往往"看起来是对的"。

# 六、这个框架能推出的两件事

**一、哪一环没落点，就是哪一环最危险。**

已查证：Geant4 里

| 环 | 有落点吗 |
|---|---|
| 环 0 要什么物理量 / 容差 / 归一化基准 | **完全没有**（`G4RunManager` 成员表里没有，grep 零命中） |
| 环 5 绝对强度 | **没有**（`/gps/source/intensity` 只是多源间的相对比例） |
| 环 6 响应系数 / 剂量转换 | **没有**（全源码树 ICRP 只出现在材料名里） |
| 环 1 统计误差 | **框架不算也不输出**（`G4StatDouble::rms()` 有实现但**全树零调用**） |
| 其余环 | 有落点，但可读性参差 |

**这五处正是"程序不问、用户就以为不需要"的地方**，也正是 AI 会自己悄悄定的地方。

**二、能推出任务集。**

每一环都有它的可变量，任务只要"把某一环的可变量换掉、看结果变不变"就成了一道题。24 题就是这么来的——T3 系列打环 5，T4 系列打环 1 和环 5，T5 打环 1，T6 打环 1、环 4b、环 6。

# 遗留

- 这张链条目前**只在 24 题上验证过能覆盖 14 个错**，没做过"AI 照着走能不能改对"的实测。
- 环 0 那五处（没有落点的）怎么问，还没有具体形态。问法是关键：不能问"归一化怎么设？"，要问"你要的是每源粒子还是每秒？"。
- 环 2「发生什么」在代码链上没有独立落点——它由环 3 的过程自动产生。所以环 2 是一个**纯推导环**，自查时只能通过环 3 间接查。
- E 类错（凭记忆写谱数据）从链条上只能"发现环 5 的输入来自手写表"，**对不对要靠外部数据**。目前还没做数据核对工具。
