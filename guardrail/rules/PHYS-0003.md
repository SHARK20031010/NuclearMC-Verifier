## 现象

某个模型负责的能量区间，在一次动作之后变了，但**没有任何日志提到这件事**。

## 为什么这是最危险的一类

因为它**不产生任何新东西**，只改一个数。任何"拍快照看现状"的办法都可能漏：
改了又改回来，完全看不见。

## 关键：为什么要在写操作"之前"拍

源码里的真实顺序是：

```cpp
(hpel->GetHadronicInteractionList())[ni-1]->SetMinEnergy(4*CLHEP::eV);  // ★ 先改
hpel->RegisterMe(new G4ParticleHPThermalScattering());                  // ★ 后注册
```

`SetMinEnergy` 在 `RegisterMe` **之前**。如果只在 `RegisterMe` 前后各拍一张快照，
两张里 Emin 都已经变成 4 eV，diff 为空 —— **抓不到**。

所以本方法维护"上次观察状态"缓存：拦截到写操作时，**先和缓存 diff 报差异**，
再执行真实调用，再更新缓存。顺序是 `drift → log → real → cache`。

## 更麻烦的一点

`G4HadronicInteraction::SetMinEnergy` 是**头文件里的 inline 函数**
（`G4HadronicInteraction.hh:89-90`），运行期没有符号可拦。

这不是 Geant4 的特例 —— 任何 header-inlined setter 都拦不住。
所以只能靠"动作前后状态 diff"来兜。
